1 Introduction

This document specifies the software interface to the hardware watchdog of the Example Platform. The watchdog is a timer outside the main processor. If it is not triggered before its timeout expires, it resets the machine. The Process Manager [EP-SWS-PM] is the only intended user of the interface: it triggers the watchdog as long as the supervised application processes behave correctly.

The interface hides the differences between the watchdog devices of the supported boards. Applications never access the device directly.

2 Interface

2.1 WatchdogClient

The interface is a single class in <ep/wdg/client.h>. Opening the client arms the watchdog; from then on it must be triggered within the timeout.

namespace ep::wdg {

class WatchdogClient {
public:
    // Opens the watchdog device and arms it. Fails if it is already open.
    static std::optional<WatchdogClient> Open();

    // The timeout of the device. Constant while the client is open.
    std::chrono::milliseconds GetTimeout() const;

    // Restarts the timer of the device.
    void Trigger();

    // The reason of the last reset: power-on, watchdog or software.
    ResetReason GetLastResetReason() const;
};

}  // namespace ep::wdg

2.2 Requirements

[SWS_WDG_00001] Exclusive access

WatchdogClient::Open shall fail if another client is open on the machine.

Derived from: EP-OVR-0120

[SWS_WDG_00002] No disarming

Once armed, the watchdog shall not be disarmed by software. Closing the client or ending the process that holds it shall leave the watchdog running.

Derived from: EP-OVR-0121

[SWS_WDG_00003] Trigger cost

WatchdogClient::Trigger shall return within 50 µs and shall not allocate memory.

Derived from: EP-OVR-0122

[SWS_WDG_00004] Trigger interval

The user of the interface shall trigger the watchdog at least three times per timeout. The Process Manager does this as required by SWS_PM_00059 of [EP-SWS-PM].

Derived from: EP-OVR-0123

3 Timing

The timeout is fixed per board and cannot be changed at run time. The values below include the tolerance of the watchdog oscillator; the effective timeout may be up to the stated tolerance shorter than the nominal value, so the trigger interval must be computed from the minimum.

[SWS_WDG_00006] Reported timeout

WatchdogClient::GetTimeout shall return the minimum timeout of the board, not the nominal one.

Derived from: EP-OVR-0124
Note: With a minimum timeout of 238 ms the Process Manager triggers the watchdog about every 79 ms. Its deadline supervision checks (section 6.2 of [EP-SWS-PM]) run in the same loop and must finish well within that time.

4 Reset reasons

After a reset the platform reads the reset reason from the device once and keeps it until the next reset. A reset by the watchdog is logged at error level by the Process Manager when it starts.

ValueMeaning
kPowerOnThe machine was switched on.
kWatchdogThe watchdog expired.
kSoftwareSoftware requested a reset.
kUnknownThe device does not report a reason.
Table 4: Reset reasons

[SWS_WDG_00008] Reason after watchdog reset

GetLastResetReason shall return kWatchdog after a reset caused by the watchdog, also when the reset happened while the device was being opened.
